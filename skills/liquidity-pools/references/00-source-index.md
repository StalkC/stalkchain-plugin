## How to interpret the references

- Matched deployed code and block/slot observations govern deployment conclusions. Pinned code and documentation describe intended behavior, not deployed equivalence.
- Historical observations in these references are inherited research notes, **not live verification performed by installing or using this package**. Raw RPC requests/responses and replay artifacts are not shipped. Reproduce relevant reads independently before relying on a live-state claim; opening an RPC endpoint URL does not reproduce an observation.
- No complete launch position is certified `verified_locked` and no migration tranche is certified `verified_burned_lp` by this package. Preserve narrower observations and unknowns.
- Community statements are attributed hypotheses, not audited profitability. Missing media, incomplete threads and inaccessible sources limit conclusions.
- Audit PDFs have their own dates, reviewed commits and scopes. They are not a remediation matrix, current deployment audit or endorsement.
- Short document/claim labels in the prose are descriptive research labels, not links to a bundled manifest. Use the adjacent public citation and pinned revision to inspect the evidence.

## Reproducibility boundary

The upstream private research commands, math scripts, unit tests, manifests and acquisition reports are **not shipped** and are not plugin commands or installation prerequisites. References retain stated formulas, illustrative inputs, historical outputs and pinned official test vectors so readers can check them independently. No upstream math test, Solidity suite, backtest or live verification is claimed to have run as part of this package release. Inline Python examples can be run separately; numerical examples are not execution quotes.
